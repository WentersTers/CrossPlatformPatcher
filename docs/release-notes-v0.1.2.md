# PAIcom Voice Release v0.1.2 — Release Notes (DRAFT for read-through)

> Status: draft. Product-voice call before publish.

## What this is

One download per system gives you a voice layer for PAIcom: talk to the
game instead of clicking through menus. Pick the file for your system:
the Windows zip holds the patcher plus the virtual-audio driver installer;
the Linux zip holds the Linux patcher and needs nothing else. Copy the
patcher into your PAIcom folder and run it from a terminal there (see
"How to run it" below) — double-clicking it only shows the help text.
It patches a copy of the game (keeping a backup if you ask), and starts
the chain. Say the wake word, say a command, and the game responds.

This release is unsigned. The Verify section at the bottom shows how to
check your download is genuine.

## What's new in v0.1.2

- Tiered voice: the offline Vosk recognizer answers first, and the
  built-in Windows speech stack covers for it whenever Vosk is
  unavailable — on Windows you are never left without voice.
- First-success-wins dispatch: the fastest confident channel claims each
  command, so duplicate handling is gone.
- Model auto-flattening: if the voice model files sit inside a
  subfolder (either next to the game or in your home models folder),
  they are moved flat automatically before startup — no manual
  rearranging. Set `PAICOM_VOSK_NO_FLATTEN=1` to keep the old behavior.
- First-run model fetch: if no model is present at all, the patcher
  downloads the small offline model once startup has settled, instead
  of failing.
- Boot-crash fix: nothing touches the network during startup anymore,
  so the game's own startup checks can't collide with ours.
- Pre-flight gates: the patcher now warns up front on raw vendor builds
  that need deobfuscation first, instead of producing a binary that
  dies in the form constructor.

## Known issues (tracked, not new)

If something below matches what you see, we already know — no need to report it.

<!-- KNOWN-BEGIN: generated by scripts/release/release-win.ps1 from structured data. Do not hand-edit. -->
- **Pop-ups that keep coming back:** An info pop-up (for example the Discord invite) may appear every time the app starts, even after you dismiss it. Known, being worked on. Dismissing it is safe; nothing breaks.

- **Slow starts and browser-tab bursts on poor connections:** On a slow connection the app can take a while to start, and a voice command may open several browser tabs at once. Known, queued behind the network work.

- **Menu buttons that do nothing:** Some game buttons in the menu do not launch anything when clicked. Expected in this version; game wiring is planned work, not a broken install.

- **Startup error pop-up when the voice model sits in a subfolder:** If the voice model files are inside a subfolder of the models folder, the game could show a .NET error box about a secure channel and then miss its start button. Mitigated in this version: the launcher moves a subdirectory model flat before startup automatically, and the recognizer does the same when it resolves one (set PAICOM_VOSK_NO_FLATTEN=1 to keep the old behavior). If the box still appears, check your connection and start again.

- **False wake-ups on echo or background sound:** The assistant may occasionally wake on an echo, music, or similar-sounding background noise. Known; a debounce fix is queued for the next revision.

- **Small model mangling unusual words:** The small offline model can mangle rare words or names; recognition still routes safely rather than running the wrong command. Known model limitation, not blocking; a larger-model option is future work.

## How to run it

You run it from a terminal, in your PAIcom folder, naming the game file.
(Double-clicking the patcher only flashes the help text.)

Windows (Command Prompt, in the PAIcom folder):

```
CrossPlatformPatcher-0.1.2-win-x64.exe PAIcom.exe --backup
PAIcom.patched.exe
```

Linux (shell, with the game path adjusted to yours):

```
chmod +x CrossPlatformPatcher-0.1.2-x86_64.AppImage
./CrossPlatformPatcher-0.1.2-x86_64.AppImage /path/to/PAIcom.exe --backup
```

The first command writes `PAIcom.patched.exe` next to the original (and
`PAIcom.exe.bak` as a backup, because of `--backup`). The second command
starts the patched game — that is the file you play from now on. Add
`--dry-run` to the first command to preview what would change without
writing anything.

## What you need

- Windows 10/11 x64 (for the `.exe`) or 64-bit Linux (for the `.AppImage`),
  with PAIcom installed.
- The patcher brings its own voice model and speech component (both
  included — if the speech component ever crashes, commands still route
  safely instead of misfiring). If no model is found anywhere, it fetches
  the small one once on its own. It does not install system software: if
  anything ever asks for the VC++ runtime, that is the free Microsoft
  installer most gaming PCs already have.
- Virtual audio cable (only needed if you play game audio back into the
  voice input): included as `VBCABLE_Driver_Pack45.zip`, unmodified.
  Extract it, run `VBCABLE_Setup_x64.exe` as Administrator, reboot, and set
  CABLE Output as the default recording device.
  VB-CABLE is donationware by VB-Audio Software — if you find it useful,
  please donate for your license on the VB-Audio webshop.

## Tested, on three operating systems

We tested all 109 voice commands on Linux, Windows 11, and Windows 10.
Every command either did the right thing or safely did nothing — none of
them ran the wrong command. That last part matters: the previous version
could match the wrong command when it misheard the wake word, and that is
fixed here. Recognition quality varies slightly between systems, and it
held up on all three, including the weakest setup we measured.

## Safety check on first run (optional, dismissable)

The first time the patched game starts, a one-time message tells you
whether its files still match the state the patcher left them in. You can
dismiss it forever (deleting the `.tripwire-seen` file next to the game
brings it back), and it never blocks the game.

Plain truth about what it is: a tamper signal for your peace of mind, not
a security boundary. It catches accidental changes, not a determined
attacker.

## How this release was built

- Reproducible builds: rebuilding these sources produces byte-identical
  files, so each hash below proves what source built it (verified by
  building twice and comparing).
- Contents check per release (automatic): the bundle carries only our own
  code, models, and runtimes — a scan confirms no game files inside.
- Tests: 307/307 passing at release time.
